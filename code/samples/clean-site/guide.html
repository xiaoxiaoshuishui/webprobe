使用指南

本节覆盖核心概念、配置项与常见用法。所有示例代码都是静态文本，不会执行。

核心概念

Clean Docs 把文档拆成三个层次，便于按需查阅：

  • 指南（Guide） — 面向任务的操作说明，回答"怎么做"。
  • 参考（Reference） — 面向字段的精确描述，回答"是什么"。
  • 示例（Samples） — 可直接对照的最小可运行片段。
{
  "name": "clean-docs",
  "version": "1.4.2",
  "strict": true
}

配置项

字段类型默认值说明
namestring—站点标识，用于生成导航与面包屑。
versionstring1.0.0语义化版本号，显示在页脚。
strictbooleanfalse开启后，文档中未解析的引用会导致构建失败。
localesstring[]["zh-CN"]启用的语言列表。

最佳实践

  • 一个页面只解决一类任务，标题用动词开头。
  • 示例代码保持可复制粘贴，不要省略导入语句。
  • 每个结论都给出可验证的判断标准。
  • 新用户：从快速开始进入。
  • 集成方：先读配置项，再读错误处理。
  • 运维：关注服务状态与版本变更记录。

错误处理

本站点自身的脚本遵循同一套约定：

  • 异步链路一定以 .catch() 收尾，绝不产生未处理拒绝。
  • 可预期的失败用界面提示表达，而不是打印 console.error。
  • 不阻塞主线程：一切耗时操作都拆成有界的小步骤。
