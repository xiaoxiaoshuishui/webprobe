# prompt/ — 与大模型交互产生并调试本平台的完整对话过程

本目录按要求（`软件安全小项目.pdf`）存放"你和大模型交互产生该软件测试平台并调试的完整对话过程"。

## 文件说明

| 文件 | 内容 |
| --- | --- |
| `01-requirements.md` | 需求读取阶段：如何从 PDF 中提取要求，以及最终确认的需求条目 |
| `02-recon-and-design.md` | 环境侦察与架构设计阶段：确认可用能力、发现沙箱限制、确定技术选型 |
| `03-build-log.md` | 编码阶段：各模块的产生顺序与设计理由 |
| `04-debug-log.md` | 调试阶段：**每一次真实失败、根因与修复**（这是本文档最有价值的部分） |
| `05-subagent-prompts.md` | 并行委派给子代理的两份完整提示词原文 |
| `06-verification.md` | 最终验证证据：自检结果、虎牙实测结果、录像 |

## 阅读建议

如果只想了解"这个平台是怎么被造出来的"，按 01 → 02 → 03 → 04 → 06 顺序阅读。
如果关心"为什么某些设计是这样"，直接看 `04-debug-log.md`——平台中几乎每一个检测规则
都对应那里记录的一次真实误报或漏报。

## 说明

本记录按时间顺序整理，忠实反映实际发生的过程：包括走过的弯路、被推翻的初版实现、
以及被平台自身的自检用例抓出来的缺陷。凡是平台自己发现的问题，都标注了
`[自检发现]`；凡是靠外部观察发现的问题，标注了 `[实测发现]`。
