本目录按要求（`软件安全小项目.pdf`）存放"你成功运行软件测试平台对任意软件进行测试的录像"。

## 内容

| 文件 | 说明 |
| --- | --- |
| `huya-live-test-run.mp4` | **运行录像**。时长约 3 分 27 秒，1280×800，H.264。内容是测试平台驱动真实 Chromium 对**虎牙直播 Web 端**进行动态测试的完整过程：依次打开首页 → 全部直播 → 游戏分类 → 手游站 → 各游戏分类页，执行声明式用户流程（展开顶部导航、搜索框联想、关闭广告位、悬停直播间卡片、深度滚动）与受控模糊测试 |

## 录像是怎么产生的

不是人工录屏，而是**平台自己录的**：`code/src/core/recorder.mjs` 使用 Chrome DevTools 协议的
`Page.startScreencast` 域抓取 JPEG 帧，**每一帧都带有它产生的时刻**，
再用 ffmpeg 的 concat demuxer 按这些时间戳设定每帧的显示时长。

因此录像的播放速度与真实的测试速度一致，而不是按猜测的固定帧率拼出来的
（本次共 4000 帧，合成后 4.7 MB）。

## 这次运行的结果

```
时长 5分18秒 · 访问页面 7 · 执行动作 91 · 网络请求 4000（失败 104）
新标签页 30（审计 1，按 URL 策略跳过 29）
发现缺陷 26 个（严重 0 · 高 1 · 中 3 · 低 22）
其中第一方（虎牙自身）17 个 · 第三方（内嵌广告/统计/微信小游戏 SDK）9 个
```

代表性缺陷：

1. **高** — 未处理的 Promise 拒绝，且拒绝原因是 `null`（`/l` 页面，异步链路静默失败）
2. **中** — 混合内容：HTTPS 页面加载了 `http://live-cover.msstatic.com/...` 的不安全图片
3. **中** — 存在 `<img src="">`，空 src 被解析为当前页面地址，对页面自身发起无效请求
4. **中** — 关键容器 `ul#wrap-recomGame` 已渲染却既无文本也无媒体元素
5. **低** — `id="live-0"` 在同一文档中重复出现 12 次

## 复现这次运行

```bash
node code/src/cli.mjs run --target code/targets/huya-live
```

由于目标清单里固定了 `seed: 20261016`，**同一随机种子会复现同一执行序列**；
但线上页面的内容与第三方请求是实时变化的，因此每次运行的缺陷集合不会完全一致。
